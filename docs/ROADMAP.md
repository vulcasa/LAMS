# LAMS 后续更新计划与路线图

> 当前基线：v1.0.0
> 当前真实库：约 4,208 部、6,892 个文件、54,608 个资产
> 说明：具体功能设计保留在 `docs/PLAN-v1.1.0.md` 与 `docs/PLAN-tape-initialization.md`，本文负责**版本排序和优先级**。

---

## 1. 总原则

后续更新按以下顺序取舍：

1. **数据安全优先**：磁带初始化、备份、还原、迁移必须先于新功能；
2. **运行可靠性优先**：CI、任务可恢复、错误可诊断；
3. **局域网优先**：远程访问必须先有认证；
4. **按需转码**：不为全库预生成移动端副本；
5. **不做无收益扩容**：4,208 部规模不换 PostgreSQL；
6. **每个版本可验证**：有明确验收标准和回滚路径。

---

## 2. 版本总览

| 版本 | 主题 | 目标 |
|---|---|---|
| **v1.1.0** | 可靠性加固 | 磁带初始化、备份可还原、CI、数据库迁移、抽帧并行 |
| v1.1.x | 日常维护优化 | 资产健康、SMB 触发、日志与错误体验 |
| v1.2.0 | 远程与元数据 | 认证、GPU 转码/HLS、FC2PPV / HeyDouga / KIN8 / 欧美片 |
| v1.3+ | 智能字幕 | ASR + 翻译、OCR 硬字幕 |

---

## 3. v1.1.0：可靠性加固（P0）

### 3.1 磁带初始化与 ltfsck 恢复（P0，最高）

详细方案：

- `docs/PLAN-tape-initialization.md`

范围：

- 新空白带挂载失败识别；
- 读取 barcode 与 `LibraryVolume` 对比；
- 已登记条码禁止格式化；
- 未登记先提供 `ltfsck` 恢复；
- 用户不恢复/恢复失败后再进入格式化；
- 弹窗输入条码；
- 可选 `mkltfs -f` 强制格式化；
- 自动挂载并登记卷；
- 所有操作走设备锁和 `TapeOperation`。

验收：

- 空白新带可在页面完成初始化；
- 已登记条码和挂载成功场景完全不出现格式化入口；
- 恢复失败不会自动格式化；
- 真机测试通过。

### 3.2 备份自动化与还原验证（P0）

现状：

- 已有数据库快照；
- 已有完整备份 zip（数据库 + manifest + 封面/剧照/抽帧）；
- 已有页面还原。

需要补：

- 每日数据库快照；
- 定期完整备份；
- 备份保留策略；
- 还原前自动校验 zip/sha256/数据库完整性；
- 还原后校验标题/文件/资产数量；
- 还原时维护模式，暂停后台任务；
- 定期做一次真实还原演练；
- 备份目录与主数据分离。

验收：

- 自动备份可定时执行；
- 还原后数据数量一致；
- 还原过程可中断、可回滚；
- 有备份新鲜度检查。

### 3.3 CI 与回归测试（P0）

现状：

- 855 个测试；
- 目前依赖本地手动执行。

需要补 GitHub Actions：

```text
push / PR
→ Python compile
→ pytest tests/ -q
→ 启动 smoke test
→ 关键页面 200
```

验收：

- 每次推送自动跑测试；
- 失败阻止合并；
- 测试结果可在 GitHub 查看。

### 3.4 数据库迁移规范（P0）

现状：

- SQLite + 轻量手工列迁移；
- 当前 4,208 部规模完全够用。

需要补：

- `schema_version`；
- 迁移可重复执行；
- 迁移前自动创建数据库快照；
- 大版本升级前强制备份；
- 记录迁移日志。

不要求立刻引入完整 Alembic，但要有明确版本和回滚点。

### 3.5 抽帧并行化（P1）

详细方案：

- `docs/PLAN-v1.1.0.md` 第 1–10 节

范围：

- 单标题内 2 个 worker；
- 全局最多 4 个 ffmpeg；
- 每个 ffmpeg `-threads 1`；
- 支持暂停/停止；
- 真实 NAS 基准测试后调整默认值。

验收：

- 结果数量/顺序与串行一致；
- 总耗时明显下降；
- 不造成数据库锁冲突；
- 播放/页面不被拖慢。

## 4. v1.1.x：日常维护优化

### 4.1 资产健康检查

- 缺失封面/剧照统计；
- 孤儿资产清理；
- 缩略图重建；
- 重复资产检测；
- 异常图片检查；
- 批量修复入口。

### 4.2 SMB 扫描触发优化

- 保持 SMB 自动轮询默认关闭；
- 主机侧文件复制完成后触发扫描；
- 或提供手动「刷新媒体库」；
- 避免唤醒 Unraid 休眠硬盘。

### 4.3 日志与错误体验

- 任务失败原因统一分类；
- 磁带/SMB/媒体错误可读化；
- 失败任务一键重试；
- 关键操作日志保留完整输出。

### 4.4 播放器维护

- 外挂字幕加载；
- 播放错误提示；
- 移动端控制优化；
- 播放会话异常清理。

## 5. v1.2.0：远程与元数据

### 5.1 远程访问认证（先做）

在 GPU 转码之前必须完成：

- 反向代理 + 登录认证；
- HTTPS；
- 限制并发；
- 不允许直接暴露 `/source`；
- 远程转码会话 token。

### 5.2 GPU 硬件转码 + HLS/fMP4（P1）

详细方案：

- `docs/PLAN-v1.1.0.md` 第 11 节

范围：

- 容器 GPU 直通；
- 硬件编码器；
- 源文件 / 自适应选项；
- 转码会话并发上限；
- 失败回退源文件；
- 磁带不直接转码。

### 5.3 非标来源元数据（P1）

详细方案：

- `docs/PLAN-metadata-v1.2.md`
- FC2 设计参考 `docs/PLAN-v1.1.0.md` 第 12 节

范围：

- FC2PPV；
- HeyDouga；
- 金髪天国 / KIN8；
- 欧美片（第一版以手工 URL/NFO 为主）；
- 统一 provider、官方页优先、第三方/JavDB fallback；
- 封面 + sample 剧照；
- seller/studio/tags/日期；
- 限速/缓存/失败冷却；
- 元数据完整度筛选。

## 6. v1.3+：智能字幕

详细方案：

- `docs/PLAN-v1.1.0.md` 第 13 节

范围：

- 音轨提取；
- ASR；
- 翻译；
- 外挂 SRT；
- 标记 AI 翻译；
- 人工校对；
- 硬字幕 OCR 后续单独评估。

优先级最低；没有 GPU 时只做少量按需验证。

---

## 7. 不建议纳入近期路线

- 迁移 PostgreSQL；
- 全库预生成移动端视频副本；
- 全库自动 AI 字幕；
- 远程转码先于认证；
- 引入完整微服务拆分；
- 为少量数据放大基础设施。

---

## 8. 建议的开发顺序

```text
1. 磁带初始化 + ltfsck（P0）
2. 备份自动化 + 还原验证（P0）
3. CI + 数据库迁移规范（P0）
4. 抽帧并行化（P1）
5. 资产健康 + SMB 触发（P1.x）
6. 认证
7. GPU 转码/HLS + FC2
8. ASR 字幕
```

---

## 9. 每版完成定义

一个版本完成需要：

- 功能实现；
- 单元测试/集成测试；
- 真实环境验证；
- 文档更新；
- 版本号/tag/Release；
- 回滚或备份方案；
- 不破坏现有 855+ 测试。
